# MoviePilot-Plugins

个人自用的 [MoviePilot](https://github.com/jxxghp/MoviePilot) 插件仓库。

部分插件基于上游项目做**本地补丁修复**，版本号在末位递增（如 `3.0.0` → `3.0.0.2`），
用于区分「上游原版」与「本仓库打过补丁的版本」。

## 安装

在 MoviePilot 中把本仓库加入插件市场：

```
设置 → 插件市场 → 添加仓库地址
https://github.com/cyh303/MoviePilot-Plugins
```

随后在「插件市场 → 未安装」里找到对应插件安装即可。V3 与 V2 两套索引同时存在，
MoviePilot 会按自身版本自动选择。

> **首次安装会较慢**：本仓库未上传 GitHub Release 产物，MoviePilot 会先尝试 Release，
> 报告「插件发布包不存在」后**自动回退为逐文件下载**。`P115StrmHelper` 共 431 个文件
> （其中 104 个多平台 wheel，合计约 29 MB），完整安装通常需要 **4–8 分钟**。
> 期间界面可能显示失败或超时，**请不要重复点击安装**，等到插件列表出现该插件再继续。

## 插件说明

### P115StrmHelper 3.0.0.2

115 网盘 STRM 生成一条龙：目录监控上传、STRM 生成、302 跳转播放、整理接管、同步删除等。

基于上游 [DDSRem-Dev/MoviePilot-Plugins](https://github.com/DDSRem-Dev/MoviePilot-Plugins) 的 `3.0.0`，叠加两个本地补丁：

**v3.0.0.1 — 目录上传漏传巡检**

修复「文件已入库但从未上传到 115」的问题：

- 新增周期巡检（默认 10 分钟）：扫描监控目录，用与写入端**完全相同的规则**推导预期 STRM 路径，
  发现「本地有视频但无同名 STRM」即重新提交上传，兜住队列卡死、插件重载/重启、监控中断造成的丢事件。
- 上传队列在停止超时后留下空队列且 worker 已退出时**自动重建**，不再永久拒绝入队。
- 上传后 pickcode 解析兼容 CloudDrive2 复合文件 ID（`<父目录id>/<文件名>` 形式），
  校验失败或 STRM 生成失败时**保留本地文件**等待重试，而不是留下无 STRM 的孤儿视频。
- 新增 `tests/test_v3_directory_upload_rescan.py`（11 个用例：候选判定、单轮上限、提交、空结果静默、
  启停幂等、队列自愈、排空期拒绝入队、pickcode 解析的纯数字/复合 id/无法解析/非法 pickcode）。

**v3.0.0.2 — 同步删除兜底匹配**

修复「在 Emby 里删了媒体，115 上的文件却没删」：

- 根因：Emby 上报的 `Container` 可能与网盘真实扩展名不一致（实测 `.mov` 文件被识别为 `mp4`），
  插件按该值拼出的路径 `xxx.mp4` 在 115 上不存在 → 判定「媒体不存在」直接跳过。
- 现在精确路径查不到时，按**文件名主干**在父目录中匹配真实文件，命中后再删除。
- 新增 `tests/test_mediasyncdel.py` 3 个回归用例（主干匹配命中、父目录缺失、删除走兜底分支）。

### P115Disk 3.0.3.1

115 网盘存储模块，按 fileid 操作，替代路径式网盘挂载。

基于上游 `3.0.3`，修复 `get_pid_by_path` 的三处缺陷：

- **命中目录后不写路径缓存**：只有「id 为 0 需建目录」的分支写了缓存，正常命中直接返回，
  导致每次列目录都要重新请求 115 接口并受 1 秒限速拖累。
- **web / app 接口交替调用**：web 版 `fs_dir_getid` 偶发返回 `405 Method Not Allowed`，
  轮到 web 那次失败即返回 `-1`，上层据此判定「目录不存在」→ **列目录间隔性返回空**。
  改为 **app 接口优先、web 仅作回退**。
- **id 未归一化**：115 返回的 `id` 是字符串，`"0" != 0` 使上层 `== -1` 判定失效；现统一转为 `int`。

新增 `tests/test_p115_api_get_pid.py`（6 个用例）。

> 注意：`P115Disk` 的 `list` / `move` / `rename` / `copy` 各有限速（0.5 QPS），
> 批量整理会比路径式挂载慢，这是防 115 风控的设计取舍。

### SehuaSignIn 2.1.0

色花堂 / 98堂（Discuz 论坛）每日自动签到。

- 内嵌浏览器通过 Cloudflare 与年龄确认页，账号密码 + 安全提问登录。
- 自动解答四种验证码：`rotate`（旋转）、`slide`（拖动滑块）、`drag`（拖拽贴图）已实现；
  `click`（点选）未实现，采用重试规避。
- 支持定时执行、手动运行、执行记录与通知。
- v2.0.0 起**移除论坛浏览与回复功能**，只保留签到。

> 需自备可用的代理与账号（账号、密码、安全提问答案仅存于本机插件配置，不在源码内）。

## 版本号规则

```
上游版本            本仓库版本
3.0.0        →      3.0.0.1  （第一个本地补丁）
             →      3.0.0.2  （第二个本地补丁）
```

- 前三段与上游保持一致，方便对照。
- 第四段仅在**本仓库打了补丁**时递增；无补丁的插件直接沿用上游版本号。
- 插件自身版本（`version.py` / `plugin_version`）与 `package.v3.json` 中的 `version` 始终同步。

## 常见问题

**装完版本号没变？**
`package.v3.json` 的 `version` 与插件自身 `version.py` / `plugin_version` 必须同时更新，
只改一处会出现「索引显示新版本、运行时仍是旧版本」。本仓库已保持同步。

**升级会不会丢配置？**
安装只替换代码，配置保存在 MoviePilot 数据库，不受影响。仍建议升级前在
`设置 → 插件 → 备份` 或手动留一份配置快照。

**能跟踪上游更新吗？**
可以。把仓库地址加入插件市场后，MoviePilot 会读取本仓库的 `package.v3.json`；
本仓库版本号高于当前安装版本时即提示更新。

**为什么没有 Release 包？**
本仓库按需构建、不发布 Release 产物，安装走文件列表回退，因此较慢（见上文）。
